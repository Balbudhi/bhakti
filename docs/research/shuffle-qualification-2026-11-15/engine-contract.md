# Pure shuffle engine contract — review before implementation

Owned files: assets/shuffle.js, scripts/test_smart_shuffle.js, scripts/benchmark_shuffle.js in /tmp/bhakti-shuffle-20261115. No queue integration changes.

API: UMD/CommonJS `BHAKTI_SHUFFLE.order(items, options)` returns `{items, score, baselineScore, stats}`; `score(items, options)` evaluates the same objective. Options: uint32 `seed` (default 0), integer `fixedPrefix` length (default 0), `profiles` plain object keyed queueId, `algorithm` random/ils/mmas (default ils), `budget:{constructions:8, localProposals:256}`, `archiveSize:8`, `qualitySlack:0.02`. Slack is absolute objective per movable occurrence; output may be this much worse than best but never worse than the seeded Fisher–Yates baseline. `stats` reports constructions, extensionEvaluations, fullEvaluations, localProposals, acceptedMoves, archiveSize, bestScore. Deterministic work limits rather than wall-clock aborts keep seed replay stable.

Profiles use the agreed public projection `{semantic:{status:'accepted'|'unavailable', themes:[{id,weight}], actions:[{id,weight}], subjects:[{id,role,weight}]}, audio:{status:'accepted'|'unavailable', physical:{whole:{integratedLufs,truePeakDbfs,rmsDbfs,centroidHz},profiles:{beginning:{...},body:{...},end:{...}}}}}` keyed queueId. Consume only accepted components. Semantic continuity uses centered weighted Jaccard (1-2*overlap), with subject roles part of identity. Audio fields use fixed physical normalization: levels clamp to [-60,0] dB except true peak [-60,+3], positive centroid logarithmically clamps to [20,20000] Hz; nonfinite values are unavailable. Centered absolute differences compare body/whole and directed end→beginning. No tempo/mood/energy inference. Missing either operand contributes exactly zero under fixed weights, without reweighting surviving components. Repetition penalties concern known themes/actions and repeated recordings. With no accepted metadata, use seeded random behavior (including intentional repeated recordings), avoiding unsupported smart ordering. Weights are provisional configuration, not a claim of listening qualification.

Test/benchmark-only options `transitionCost(previous,item)` and `windowCost(recent,item)` override the corresponding default component; `windowSize` defaults 4. They make arbitrary directed/window objectives independently testable. Every callback must return a finite number or throw. The objective sums contributions only at destinations >=fixedPrefix, using inherited prefix context; score has no closing/cycle edge.

Every original occurrence/reference appears exactly once, even when queueId or object reference repeats. Never deduplicate. Prefix positions/references remain identical. Do not mutate inputs or profiles. Empty/all-fixed/singleton are valid. Invalid prefix/seed/budgets/algorithm rejected. Budgets have validated upper caps (constructions<=64, proposals<=20000); zero budgets return seeded baseline.

Both methods start with the identical seeded Fisher–Yates baseline and share one bounded swap/relocate local improver. Initial implementation fully recomputes the objective for each move (directed/window correctness over speculative delta optimizations). One global local-proposal counter caps all calls. ILS perturbs the incumbent/restarts and invokes the common improver. MMAS-derived construction: pheromone frozen within generations, all remaining candidates eligible; stable exp-normalized cost heuristic with uniform exploration; generation-best reinforcement, evaporation, clipping and bounded stagnation reset. No ACS claim, no persistent pheromone, no inference calls. Fixed generations of up to 4 ants share the total construction budget. Local allowance is divided across construction slots to prevent first candidate consuming all work. Rank-style constant best-edge deposit is explicitly an MMAS-derived adaptation, not canonical inverse-length MMAS.

Archive retains distinct occurrence-index permutations near the best objective; deterministic seeded sampling supplies variety. No uniform position exposure/global optimality/listening-quality claim. A guaranteed baseline member/fallback bounds degradation. Exported score is independent of algorithm and RNG.

Tests before code: API/validation, empty and fixed-prefix boundaries, repeated occurrence conservation/immutability, exact seeded replay and across-seed variation, missing/nonfinite evidence neutrality, asymmetric/anchor/window fixture score against independent evaluator, exhaustive small permutation oracle bound, strict budget counters and no-worse-than-baseline output. Benchmark separately reports un-improved construction and equal local-improvement budget, synthetic clustered/outlier/missing data, real catalogue if available, seeds and runtimes. Exact small cases assess numerical optimization only; synthetic/catalogue scores do not establish listener preference.

Scale bound: >512 input occurrences starts seeded Fisher–Yates and runs the common full-score local improver capped at min(requested localProposals,16), records `fallback:'mmas-to-local-budget'` for MMAS or `large-local-budget` for ILS, and preserves the entire occurrence multiset (supports existing 4096-entry queues). No quadratic matrix or constructive search is allocated in this path. Random remains random. Fresh orders select the first occurrence uniformly via baseline Fisher–Yates and hold it during search; only explicitly supplied fixedPrefix changes objective history accounting. No external I/O.

Implementation order for review: validate inputs and seeded baseline → accepted-profile projection/pair and window evaluator → full-score common local improver and bounded archive → ILS → MMAS-derived constructor/update → benchmarks. Scorer correctness precedes search; queue integration remains parent's independent ownership.

Benchmark-only `disablePheromone:true` removes pheromone from the MMAS transition probabilities while retaining heuristic, construction count, and common local improver for attribution. Browser export is globalThis.BHAKTI_SHUFFLE; CommonJS export is the same object.

Default fixed weights: semantic theme0.5/action0.2/role-matchedsubject0.2; body/wholephysical0.1; directedend→beginningphysical0.2. Each physical component is the sum of centered differences over four fixed fields divided by4 (missing contributes0). Window:0.4 for each same recording in last4 if both have accepted metadata;0.25 for each additional prior overlap beyond the first among accepted theme sets in last4. Missing themes do not count. Custom callbacks replace pair/window terms entirely. WindowSize integer0..16, archiveSize integer1..32, qualitySlack finite0..1; constructions integer0..64 and localProposals integer0..20000. Reject invalid rather than truncate. These are explicit provisional engineering defaults, not empirically qualified perceptual weights.
